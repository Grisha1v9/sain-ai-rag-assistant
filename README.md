# Sain AI: RAG-ассистент по сну (Hackathon Case 4)

Бэкенд и AI-модуль для приложения Sain, разработанный в рамках хакатона от Сбера и «Школы 21». Ассистент отвечает на вопросы пользователей о сне, опираясь строго на базу из 20 научных статей (на английском языке), и отыгрывает роль одного из трех вымышленных экспертов.

> **Моя роль:** AI / Backend Engineer (разработка всей серверной логики, RAG-пайплайна, промпт-инжиниринга, Guardrails).

---

## Ключевые достижения (Engineering Highlights)

В условиях жестких ограничений хакатона (сервер на **512 МБ RAM, 1 CPU**, **отсутствие доступа в интернет** из контейнера) были реализованы нетривиальные архитектурные решения:

- **Явный State Machine на LangGraph:** Пайплайн обработки запросов переведен с ручного императивного кода на декларативный граф состояний (`StateGraph`). Это обеспечило строгую изоляцию узлов (кэш, роутинг, RAG, генерация), упростило отладку и заложило фундамент для добавления новых агентов (например, верификации фактов).
- **LLM-Router вместо Vector DB:** Из-за невозможности скачать модели эмбеддингов (нет интернета) и лимита памяти, классический векторный поиск (FAISS/Chroma) не подходил. Был написан **Semantic Router** на базе LLM, который по заголовкам статей и разделов выбирает релевантный источник под русскоязычный вопрос пользователя. Отдельный узел валидирует возвращённые ID, чтобы галлюцинация роутера не сломала ответ.
- **Умные Guardrails (Safety):** Двухуровневая защита. Быстрый Regex отсекает очевидные атаки, а LLM-роутер определяет скрытые попытки получить медицинский совет (например, просьбы оценить «лайфхак»). Для отказов динамически снижается лимит `max_tokens`, чтобы не тратить бюджет генерации на развернутый ответ.
- **Кэширование троек (Compliance):** По требованиям кейса, три разных эксперта, отвечающие на один и тот же вопрос, обязаны ссылаться на *один и тот же* раздел статьи. Реализован глобальный кэш `(article_id, section_id, attack)` с ключом по нормализованному тексту вопроса — это гарантирует одинаковые ссылки и одинаковый флаг отказа для всех экспертов в тройке.
- **Fallback на BM25:** Если нейросеть падает (ошибки API, 429 Too Many Requests), система не выдает 500-ю ошибку, а автоматически переключается на лексический поиск `BM25Okapi`. Ограничение: лексическое совпадение слабо работает на паре «русский запрос — английская статья», поэтому это именно резервный путь, а не основной поиск.
- **Persona Engineering:** Созданы 3 системных промпта, задающих уникальный стиль речи (строгий клиницист, энергичный биохакер, заботливый нутрициолог).

## Архитектура и Стек

- **Язык:** Python 3.11
- **Фреймворк:** FastAPI, Uvicorn
- **Оркестрация:** LangGraph (StateGraph)
- **LLM:** `gpt-6-luna` (через прокси, OpenAI SDK)
- **Поиск:** `rank_bm25` (лексический фолбэк)
- **Валидация:** Pydantic

### Граф обработки запроса

- `check_cache` — поиск нормализованного вопроса в кэше троек;
- `router_and_guard` — LLM-роутер (определение атаки + выбор статьи и раздела), при сбое — Regex + BM25;
- `retrieve_context` — валидация ID и извлечение текста раздела (обрезка до 1200 символов);
- `build_prompt` — системный промпт персоны (+ блок отказа при атаке) и промпт с контекстом;
- `generate_answer` — вызов LLM;
- `save_to_cache` — запись тройки в кэш.

Условное ребро после `check_cache`: при попадании в кэш граф пропускает роутер и идет сразу к извлечению контекста, экономя вызов LLM.

### Структура проекта

```text
├── app/
│   ├── __init__.py
│   ├── main.py              # Точка входа FastAPI, эндпоинты /run и /chat

├── requirements.txt
├── start.sh
└── .env.example             # Пример секретов
```

## Локальный запуск

**1. Клонируйте репозиторий и создайте виртуальное окружение:**

```bash
git clone https://github.com/Grisha1v9/sain-ai-rag-assistant.git
cd sain-ai-rag-assistant
python -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate
```

**2. Установите зависимости:**

```bash
pip install -r requirements.txt
```

**3. Настройте переменные окружения:**

Создайте файл `.env` на основе `.env.example` и добавьте ваши ключи (для локального теста можно использовать любой OpenAI-совместимый API):

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_API_KEY=your_api_key_here
LLM_MODEL=gpt-4o-mini
PORT=8000

# Нужен только для эндпоинта /run (скачивание датасета хакатона).
# Если не задан, используется значение по умолчанию.
HACK_API_URL=https://hack-api.be-healthy.tech
```

**4. Запустите сервер:**

```bash
bash start.sh
# или
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

## Использование API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Статус сервиса: `{"status": "ok"}` |
| `GET` | `/health` | Healthcheck |
| `POST` | `/chat` | Одиночный вопрос эксперту |
| `POST` | `/run` | Пакетная обработка датасета (Bearer-токен) |

### 1. Одиночный чат (`/chat`)

Допустимые значения `expert_id`: `clinician`, `biohacker`, `nutritionist`.

**Запрос:**

```bash
curl -X POST "http://localhost:8000/chat" \
     -H "Content-Type: application/json" \
     -d '{
           "text": "Сколько мг мелатонина мне выпить перед сном?",
           "expert_id": "clinician"
         }'
```

**Ответ:**

```json
{
  "text": "Я не могу назначать конкретные дозировки препаратов...",
  "refused": true,
  "citations": [{"article_id": "art_03", "section_id": "s002"}]
}
```

Поля ответа: `text` — текст ответа эксперта, `refused` — признак отказа (запрос распознан как недопустимый), `citations` — источник из базы статей, на который опирается ответ.

### 2. Пакетная обработка (`/run`)

Используется автоматической системой оценки хакатона. Скачивает датасет по коду набора, прогоняет все запросы через пайплайн и возвращает массив ответов в формате JSON. Требует передачи Bearer-токена в заголовке `Authorization`.

## Планы развития (Post-Hackathon Roadmap)

Проект успешно решил задачу хакатона, но имеет четкий план архитектурных улучшений для production-использования:

1. **Расширение графа LangGraph:** Добавление узла верификации фактов (`validate`) после генерации и узла автоматической оценки ответов (LLM-as-a-Judge). Подключение `MemorySaver` и `thread_id`, чтобы `/chat` учитывал историю диалога, а не только одиночный вопрос.

2. **Гибридный RAG с BM25 как основным:** Чтобы радикально снизить стоимость и задержку (latency), планируется сделать BM25 основным поисковиком. Для решения проблемы языкового барьера (запрос на русском, статьи на английском) будет добавлен легковесный слой предобработки: словарь для RU→EN транслитерации/перевода ключевых терминов перед поиском. LLM будет вызываться только для финальной генерации ответа.

3. **Интеграция с трекерами сна:** Расширение эндпоинта `/chat` для приема JSON-данных из Apple Health / Google Fit, чтобы персонализировать советы на основе реальных метрик пользователя (длительность фаз сна, пульс в покое).
